Design notes — read before we build

One room, three tempos. The page reads top-to-bottom as a story: the spectacle (live pots burning), the invitation (open seats filling), the record (settled hands). Green belongs to live, gold to action, cooled brass to history — the left accent bar on every card tells you which world you're in before you read a word.

Cards and rows are the same object. The rows view carries identical data in identical order (market → pot → round → players → watchers → time → action), so switching views never re-teaches the layout. Columns are a fixed grid template — every row lands on the same rails.

The create flow is a dealer's ritual, not a form. Every input is a chip you press or a seat you tap — presets first, typing never required. The "you're setting up" line rewrites itself as you choose, so the player reads back their own table before committing.

Cost is never a surprise. Both modals end on the same disclosure: buy-in + entry = total, then one gold button that repeats the number ("Take your seat · deposit 10.50 USDC"). The deposit ceremony reuses the existing TxCeremony vocabulary — Prepare → Approve → Finalize — so the wallet moment feels familiar from the first table to the hundredth.

Continuity with what's shipped. Chrome, network pill, wallet pill, coin badges, seat pips, countdown rings, LIVE tags — all lifted from the current Dashboard/WaitingRoom recipes so this page and the felt feel like one world. In the app this page renders over the live 3D table; the backdrop here is a stand-in.

Urgency is typed, not shouted. Fill rings turn amber under 60s; "One seat left" gets a flag; the final round at a live table reads "final round" in green. No red except loss/error.

The rail keeps identity in view. Your chips, record, and rank sit beside the action — the profile and leaderboard are one glance away without leaving the room. On mobile the rail stacks below the sections.

Still to design after sign-off. Spectator view entry (camera swoop + live HUD in read-only), hand replay screen, full profile page, empty states for each section, and the invite-link accept prompt.
